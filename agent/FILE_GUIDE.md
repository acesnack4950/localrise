# LocalRise 김해 관광지 추천 시스템 — 파일 안내서 (비전공자용)

이 폴더(`agent`)는 **여행객의 취향을 물어보고 김해의 맞춤형 관광지 5곳을 AI로 추천해 주는 프로그램**이 들어 있는 공간입니다.  
식당에 비유하자면 **주방(서버 프로그램)**, **레시피와 식재료(데이터 파일)**, **홀 메뉴판(화면 파일)**, **오픈 준비 도구(보조 프로그램)**로 나눌 수 있습니다.

---

## 1. 핵심 프로그램 파일 (주방의 요리사)

### `app.py` — 메인 두뇌 역할을 하는 서버 프로그램
- **쉽게 말하면:** 관람객이 고른 취향 답변을 받아서 가장 잘 어울리는 관광지 5곳을 골라주고, 추천 이유를 작성해 화면으로 보내주는 **총괄 매니저**입니다.
- **하는 일:**
  1. 관람객이 7개 질문에 답하면, 점수표(`place_traits.json`)를 보고 어울리는 후보 10곳을 추립니다.
  2. AI(OpenAI 또는 Ollama)에게 후보 10곳을 보여주고, 여행객의 성향 한 줄 요약과 최종 추천 관광지 5곳, 그리고 추천 이유를 작성하게 합니다.
  3. **거짓말 방지(검증):** AI가 실제 관광지 정보(`gimhae_places.csv`)에 없는 내용(예: 입장료 무료, 벚꽃 명소 등)을 지어내지 않았는지 꼼꼼히 검사하고 교정합니다.
  4. 혹시 인터넷이나 AI 연결이 끊기더라도 화면이 멈추지 않도록, 미리 준비된 설명 문장으로 즉시 결과를 만들어 내는 **비상 안전장치**가 들어 있습니다.

### `video_jobs.py` — 관광지 영상·사진 전달 담당자
- **쉽게 말하면:** 시연 화면의 마지막 3단계(장소 영상 보기)에서 관람객이 특정 관광지를 선택했을 때, **해당 장소의 영상이나 사진을 찾아 화면에 띄워주는 담당자**입니다.
- **하는 일:**
  - `static/videos/` 폴더에 영상 파일이 있으면 영상을 보여주고, 사진만 있으면 사진을 대신 보여줍니다.
  - 추후 클라우드 AI 영상 생성기(Comfy Cloud)와 연결할 수 있도록 미리 자리가 마련되어 있습니다.

## 2. 데이터 파일 (레시피와 식재료)

> 메모장이나 코드 편집기로 열어서 글자를 수정하면 프로그램에 바로 반영되는 데이터 파일들입니다.

### `gimhae_places.csv` — 김해 관광지 20곳 백과사전
- **쉽게 말하면:** 엑셀(표) 형태로 정리된 **김해 대표 관광지 20곳(수로왕릉, 연지공원, 롯데워터파크 등)의 공식 정보 파일**입니다.
- **들어 있는 내용:**
  - 장소 번호(`GIMHAE_001` ~ `GIMHAE_020`), 장소 이름, 카테고리(역사, 자연 등)
  - 어울리는 취향 태그(예: `역사, 산책, 가족`)와 피해야 할 취향 태그(예: `액티비티, 번화가`)
  - AI가 추천 이유를 쓸 때 참고하는 **공식 설명 문장 5개씩**이 들어 있습니다.

### `quiz.json` — 관람객에게 물어보는 7가지 취향 질문지
- **쉽게 말하면:** 화면 첫 단계에서 관람객이 고르는 **밸런스 게임(A/B 2지선다) 질문 7개**가 적힌 파일입니다.
- **들어 있는 내용:**
  1. 누구와 함께하나요? (가족·아이 vs 친구·연인)
  2. 더 끌리는 여행지는? (역사·전통 vs 자연 풍경)
  3. 원하는 분위기는? (조용·차분 vs 활기·신남)
  4. 어떤 재미를 원하나요? (보고 배우기 vs 직접 체험)
  5. 얼마나 움직이고 싶나요? (가벼운 산책 vs 활발한 활동)
  6. 언제 여행하고 싶나요? (햇살 좋은 낮 vs 분위기 있는 밤)
  7. 가장 기대되는 건? (멋진 풍경 감상 vs 맛있는 먹거리)
- 질문 문구나 중요도(가중치)를 바꾸고 싶을 때 이 파일을 수정하면 됩니다.

### `place_traits.json` — 관광지별 취향 궁합 표
- **쉽게 말하면:** 김해 관광지 20곳이 위의 7가지 질문 각각에 대해 **A에 가까운지, B에 가까운지, 상관없는지(N) 표시해 둔 채점표**입니다.
- **예시:** 수로왕릉(`GIMHAE_001`)은 테마가 `A(역사)`, 분위기가 `A(조용함)`, 시간대가 `A(낮)`으로 설정되어 있어, 관람객이 A를 많이 고를수록 높은 점수를 받습니다.

### `poi_config.json` — 관광지별 사진·영상 및 AI 그림 설정표
- **쉽게 말하면:** 관광지 20곳마다 **어떤 사진/영상 파일을 연결할지**, 그리고 AI로 이미지를 만들 때 **어떤 영어 주문문(프롬프트)을 쓸지** 적어둔 목록입니다.
- 예를 들어 `GIMHAE_001`은 `GIMHAE_001.png`(사진)와 `GIMHAE_001.mp4`(영상)를 사용한다고 지정되어 있습니다.

## 3. 관람객 화면 및 미디어 폴더 (`static/`)

### `static/index.html` — 전시회 시연용 메인 웹페이지
- **쉽게 말하면:** 관람객이 키오스크나 노트북 화면으로 직접 터치하고 보는 **본선 시연용 화면**입니다.
- **구성 (3단계):**
  - **STEP 1:** 7가지 A/B 질문 선택 화면
  - **STEP 2:** 여행자 성향 분석 결과 + 추천 관광지 5곳 카드 화면
  - **STEP 3:** 선택한 관광지의 홍보 영상/이미지를 감상하는 화면

### `static/test.html` — 관리자용 간단 테스트 화면
- **쉽게 말하면:** 디자인 요소를 빼고, 질문 선택이나 문장 입력 시 **추천 결과가 잘 나오는지 빠르게 점검해 보는 개발자·운영자용 화면**입니다.

### `static/brand/`, `static/images/`, `static/videos/` — 이미지·영상 보관함
- **`brand/`:** 화면 곳곳에 등장해 안내를 돕는 김해시 마스코트 **'토더기'** 캐릭터 이미지들을 넣어두는 폴더입니다 (`README.md`에 넣어야 할 파일 이름이 안내되어 있습니다).
- **`images/`:** 관광지별 대표 사진(`GIMHAE_001.png` ~ `GIMHAE_020.png`)을 넣어두는 폴더입니다.
- **`videos/`:** 관광지별 영상(`GIMHAE_001.mp4` ~ `GIMHAE_020.mp4`)을 넣어두는 폴더입니다. 파일을 넣기만 하면 화면에 자동으로 연결됩니다.

## 4. 전시 준비 및 대회 제출용 보조 도구

### `warmup_cache.py` — 전시 전 '미리 계산하기' 도구 (사전 준비용)
- **쉽게 말하면:** 전시회 당일 관람객이 기다리지 않도록, **가능한 모든 답변 조합(2×2×2×2×2×2×2 = 128가지)의 AI 추천 결과를 미리 다 만들어서 저장해 두는 프로그램**입니다.
- **왜 필요한가요?** AI가 실시간으로 글을 쓰면 10~40초가 걸리지만, 전시 전에 이 파일을 한 번 실행해 두면(`cache` 폴더에 저장됨) 전시 당일에는 **어떤 답변을 골라도 1초 만에** 결과가 나옵니다. 또한 추천이 골고루 잘 되었는지 분석하는 **추천 품질 리포트**도 함께 만들어 줍니다.

### `make_submission_json.py` — 대회 제출용 파일 생성기
- **쉽게 말하면:** 대회 주최 측에 제출해야 하는 **`02_LocalRise_지역추천지.json` 파일을 규격에 딱 맞춰 자동으로 만들어 주는 도구**입니다.

## 6. 변경 이력 (v2.2 → v2.3)

수정된 파일: `app.py`, `README.txt` (나머지 파일은 그대로입니다.)

### 변경점 표

| # | 구분 | 위치 (`app.py`) | 변경 전 | 변경 후 | 이유 |
|---|---|---|---|---|---|
| 1 | 오류 응답 형식 | `region_error()` (신규), `current_region()` | 지역 불일치 시 요청값을 그대로 `region_id`에 담아 반환, 그 외 오류는 FastAPI 기본 `{"detail":...}` | 모든 오류를 `{"region_id":"GIMHAE","message":...}`로 반환 (`region_id`는 본인 팀 지역) | 대회 명세 "오류 Response 권장" 준수 |
| 2 | 오류 시 안정성 | `current_region()` | 추천 과정에서 오류가 나면 그대로 500 오류 노출 | 오류가 나도 이전 결과가 있으면 그것을 반환, 없으면 오류 형식으로 반환 | 전시 중 한 번의 오류로 응답이 끊기지 않게 |
| 3 | 첫 요청 지연 | `warmup()` | 서버 시작 시 AI 키 유무만 출력 | 서버 시작 시 기본 추천을 미리 만들어 저장 | 첫 `/current_region` 요청이 AI를 기다리다 시간 초과되는 것 방지 |
| 4 | 기본 추천 공통화 | `default_result()` (신규) | 기본 추천 생성 코드가 `current_region()` 안에 따로 있었음 | 함수로 분리하고 `/recommend`와 같은 캐시 키 사용 | 제출 JSON 생성 경로와 API 경로가 같은 결과를 쓰도록 (재현성) |
| 5 | 평가 재현 모드 | `FREEZE_LATEST`(`LOCALRISE_FREEZE`), `set_latest()` | 시연 중 질문이 들어오면 `/current_region` 결과가 바뀜 | `LOCALRISE_FREEZE=1`이면 시연 입력이 `/current_region` 결과를 바꾸지 못함 | 평가 시 제출 JSON과 API 결과가 달라지는 것 방지 |
| 6 | AI 대기 시간 | `LLM_TIMEOUT` | 기본 90초 | 기본 40초 (`LOCALRISE_LLM_TIMEOUT`로 조정 가능) | 부스 HTTP 대기 단축, 실패 시 CSV 근거 문장으로 빠르게 대체 |
| 7 | 거짓 내용 검사 오탐 | `_FACT_TERMS_CANDIDATES` | 검사 단어 `"별"` (한 글자) | `"별빛"`, `"별자리"`, `"별관측"` | "특별" 같은 단어 때문에 정상 문장이 지워지는 문제 해결 |
| 8 | 문서 | `README.txt` | - | v2.3 변경·제출 주의사항 추가 | 인수인계용 |

### `/current_region` 동작 (변경 후)

```text
서버 시작 → 기본 추천을 미리 만들어 저장
GET /current_region?region_id=GIMHAE
 ├ region_id 불일치   → 404 {"region_id":"GIMHAE","message":"Requested region_id was not found."}
 ├ 저장된 결과 있음   → 바로 반환
 ├ 저장된 결과 없음   → 기본 추천을 만들어 반환
 └ 오류 발생          → 이전 결과가 있으면 반환 / 없으면 500 + 오류 형식
```

### 새로 생긴 설정값 (`.env`)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `LOCALRISE_FREEZE` | `0` | `1`이면 평가·재현 모드 (`/current_region` 결과 고정) |
| `LOCALRISE_LLM_TIMEOUT` | `40` | AI 응답 대기 시간(초) |

### 제출 전 순서

1. `.env`에 `OPENAI_API_KEY`와 `LOCALRISE_FREEZE=1` 입력
2. `python app.py` 실행 → `python warmup_cache.py` → 인자 없이 `python make_submission_json.py`
3. `cache/` 폴더를 포함해 제출 (`.venv`, `__pycache__`는 제외)
4. 제출 JSON과 `GET /current_region?region_id=GIMHAE` 결과가 같은지 확인
